Accessibility

Built to be readable by everyone.

We treat accessibility as a design constraint, not an afterthought. This site targets WCAG 2.2 Level AA and has been built with that target in mind from the first commit. This page documents what we promise, where we know we still fall short, and how to tell us when we get it wrong.

What we target

  • Contrast. Body text on the surface meets the 4.5:1 ratio AA requires; large text and UI controls clear 3:1. The token palette in tokens.css is designed against the same target and audited every time we change a colour.
  • Keyboard. Every interactive element can be reached and operated without a pointer. Focus rings are visible (2 px accent blue, with a surface offset) on every actionable element.
  • Semantics. Pages use real HTML landmarks (header, nav, main, footer), one <h1> per page, and nested headings without level jumps. A skip-to-content link is the first focusable thing on every page.
  • Motion. Every animation is gated on the user's prefers-reduced-motion preference. If reduced motion is requested, scroll-linked fades and any ambient loops freeze; the static composition is the intended fallback, not a degradation.
  • Colour scheme. Dark mode is a first-class target, not a filter. Both themes are designed and tested to the same contrast and legibility targets, and the user's chosen mode is persisted.
  • Alt text. Every meaningful image carries real alternative text; decorative images carry an empty alt="" attribute so screen readers skip them rather than announcing the filename.

How we built it

The site is static HTML — no client-side framework runtime, no single-page-application router. Pages work without JavaScript: the publications filter degrades to "show all," the mobile menu falls back to the main nav, and every link is a real anchor. Fonts are self-hosted (Fraunces, Inter, JetBrains Mono) and served with font-display: swap, so text is readable even before the web fonts arrive.

Known gaps

Things we know about and are working on:

  • Several project hero images are tasteful placeholders rather than the lab's own science. They carry meaningful alt text and contrast well, but the underlying images will be swapped for real ones as the lab provides them.
  • Embedded YouTube videos are click-to-play and use the no-cookie domain. Captions rely on YouTube's auto-caption system; lab-curated captions for the most-cited videos are on the to-do list.
  • We have not yet completed a full third-party audit against WCAG 2.2 AA. The internal pass uses semantic markup, automated checks, and manual keyboard / screen-reader walk-throughs.

Tell us when it breaks

If something on this site is hard to read, hard to operate, or fails outright with assistive technology, please email m.ghajari@imperial.ac.uk with the page URL, the assistive technology you were using, and a short description of what went wrong. We treat accessibility bug reports as first-priority work.
